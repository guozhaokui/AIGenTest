# 激活式知识库搜索引擎 - 实现总结

## 实现概览

基于您提出的"类似神经网络激活"的知识图谱检索思想，实现了一个高性能的激活式搜索引擎。

## 核心设计

### 1. 多粒度N-gram拆分

每个文档被拆分为多个层次的属性节点：

```
文档 → 属性节点集合
  ├─ 字符级: 2-gram, 3-gram (捕获未登录词)
  ├─ 词级: 2-gram, 3-gram, 4-gram (词组关系)
  └─ 语义级: 句子, 段落 (完整语义)
```

**优势**:
- 字符级能匹配拼写变体
- 词级捕获常见搭配
- 语义级保留上下文

### 2. 激活传播机制

```
查询 → N-gram拆分 → 匹配属性节点 → 激活文档节点 → 计算得分
```

**评分公式**:
```
单次激活 = gram权重 × section权重 × log(粒度+1)
文档得分 = Σ激活得分 × 覆盖率因子 + 向量相似度 × 权重
```

### 3. 数据库结构

使用SQLite实现轻量级但功能完整的知识图谱：

| 表名 | 用途 | 索引 |
|------|------|------|
| documents | 文档节点 | path, project, timestamp |
| ngrams | N-gram属性 | content, doc_id, gram_type |
| ngrams_fts | FTS5全文索引 | content |
| document_tags | 标签关系 | tag |
| document_vectors | TF-IDF向量 | doc_id |
| ngram_stats | IDF统计 | content |

### 4. 技术栈选择

| 组件 | 选择 | 理由 |
|------|------|------|
| 数据库 | better-sqlite3 | 轻量级，高性能，同步API |
| 全文搜索 | SQLite FTS5 | 内置，无需额外服务 |
| 中文分词 | nodejieba | 成熟稳定的jieba分词 |
| 向量计算 | 自实现TF-IDF | 简单有效，无需外部依赖 |

## 实现亮点

### 1. 零配置启动

```javascript
const storage = new StorageV2();
// 自动检测现有Markdown文件
// 自动构建索引
// 自动初始化向量引擎
```

首次使用自动同步现有数据，无需手动初始化。

### 2. 双存储机制

- **Markdown**: 人类可读，Git友好
- **SQLite**: 高性能检索

两者自动同步，互为备份。

### 3. 智能评分

结合三个维度：

1. **N-gram匹配**: 多粒度激活得分
2. **向量相似度**: TF-IDF语义匹配
3. **覆盖率**: 查询词覆盖程度

权重可配置，适应不同场景。

### 4. 性能优化

- **FTS5加速**: 全文搜索O(log n)
- **预编译语句**: 减少SQL解析开销
- **稀疏向量**: 压缩存储空间
- **WAL模式**: 提升并发性能
- **批量操作**: 事务包装减少I/O

### 5. 可扩展架构

模块化设计，职责分离：

```
storage-v2.js (统一接口)
  ├─ storage.js (Markdown层)
  ├─ knowledge-indexer.js (索引构建)
  │   ├─ ngram-processor.js (文本处理)
  │   └─ vector-engine.js (向量计算)
  └─ activation-search.js (搜索引擎)
```

## 潜在问题与解决方案

### 问题1: 存储膨胀

**现象**: N-gram数量是文档大小的10倍

**解决方案**:
- 过滤低价值n-gram (IDF阈值)
- 压缩存储 (使用BLOB存储)
- 定期清理 (删除无激活的n-gram)

### 问题2: 中文分词误差

**现象**: "知识图谱"可能被切分为"知识 图 谱"

**解决方案**:
- 字符级n-gram补充 (已实现)
- 自定义词典 (jieba支持)
- 多分词器融合 (未来)

### 问题3: 冷启动问题

**现象**: 文档少时TF-IDF不准确

**解决方案**:
- 降低向量相似度权重
- 增加激活匹配权重
- 引入外部语料库 (未来)
