# 激活式搜索引擎原理

## 核心思想

基于"神经网络激活"的概念，将文档分解为多粒度的n-gram节点，通过查询激活匹配的节点，再传播到所属文档进行得分计算。

## 架构设计

### 1. 数据结构

```
文档节点 (Document)
  ├─ 元数据 (Metadata)
  │   ├─ 项目名
  │   ├─ 标签
  │   └─ 时间戳
  │
  └─ 属性节点 (N-gram Nodes)
      ├─ 元数据n-gram
      ├─ 字符2-gram
      ├─ 字符3-gram
      ├─ 词2-gram
      ├─ 词3-gram
      ├─ 词4-gram
      ├─ 句子级
      └─ 段落级
```

### 2. N-gram粒度

文档被拆分成多个层次的片段：

| 粒度 | 示例 | 用途 |
|------|------|------|
| 字符2-gram | "知识", "识图", "图谱" | 捕获未登录词 |
| 字符3-gram | "知识图", "识图谱" | 增强字符匹配 |
| 词2-gram | "知识 图谱", "图谱 实现" | 捕获词组关系 |
| 词3-gram | "知识 图谱 实现" | 捕获短语 |
| 词4-gram | "知识 图谱 实现 方案" | 捕获长短语 |
| 句子 | "我们使用知识图谱实现..." | 完整语义 |
| 段落 | 整段文本 | 上下文 |

### 3. 索引构建流程

```
Markdown文件
   ↓
解析元数据和正文
   ↓
分词处理 (nodejieba)
   ↓
生成各粒度n-gram
   ↓
存储到SQLite + FTS5
   ↓
计算TF-IDF向量
   ↓
索引完成
```

### 4. 搜索流程

```
用户查询
   ↓
1. 分词和n-gram拆分
   ↓
2. FTS5快速匹配n-gram
   ↓
3. 激活文档节点
   │  计算激活得分:
   │  - n-gram类型权重
   │  - 所在位置权重 (metadata > problem > solution)
   │  - 粒度加成 (长n-gram > 短n-gram)
   │  - 匹配覆盖率
   ↓
4. 计算向量相似度 (TF-IDF + 余弦)
   ↓
5. 综合排序
   │  总分 = 激活得分 + 向量相似度 * 权重
   ↓
6. 返回Top-K结果
```

## 评分机制

### 激活得分计算

```javascript
单个匹配得分 = gram权重 × section权重 × log(gram_size + 1)

文档激活得分 = Σ(单个匹配得分) × (0.7 + 0.3 × 覆盖率)

覆盖率 = min(匹配的ngram数 / 查询ngram数, 1.0)
```

### 权重配置

```javascript
// N-gram类型权重
metadata: 5.0      // 元数据（项目名、标签）
sentence: 3.0      // 句子
word_4gram: 2.5    // 4词组
word_3gram: 2.0    // 3词组
word_2gram: 1.5    // 2词组
char_3gram: 1.0    // 3字符
char_2gram: 0.8    // 2字符

// Section权重
section_metadata: 3.0   // 元数据部分
section_problem: 2.0    // 问题部分
section_solution: 1.5   // 解决方案部分

// 向量相似度权重
vector_similarity: 2.0
```

### 向量相似度

使用TF-IDF + 余弦相似度：

1. **TF (Term Frequency)**: `tf(t,d) = count(t,d) / |d|`
2. **IDF (Inverse Document Frequency)**: `idf(t) = log((N+1)/(df(t)+1)) + 1`
3. **TF-IDF**: `tfidf(t,d) = tf(t,d) × idf(t)`
4. **余弦相似度**: `sim(q,d) = (q·d) / (|q|×|d|)`

## 技术栈

- **数据库**: better-sqlite3 (轻量级，高性能)
- **全文搜索**: SQLite FTS5 (内置，无需额外依赖)
- **中文分词**: nodejieba (jieba分词的Node.js版本)
- **向量计算**: 内存中的简单TF-IDF实现

## 优化策略

### 1. 存储优化

- **稀疏向量**: 只存储非零值 `index:value`
- **索引**: 为content、doc_id、gram_type建立索引
- **FTS5**: 加速全文搜索

### 2. 查询优化

- **批量查询**: 使用FTS5的OR查询一次性匹配多个n-gram
- **早停机制**: 限制FTS返回结果数量
- **最小得分过滤**: 过滤低分结果

### 3. 内存优化

- **延迟加载**: 向量引擎只在需要时初始化
- **连接池**: 重用数据库连接
- **WAL模式**: 提升并发性能

## 与传统搜索的对比

| 特性 | 传统全文搜索 | 激活式搜索 |
|------|-------------|-----------|
| 匹配方式 | 包含子串 | 多粒度n-gram激活 |
| 相关性排序 | 简单的出现次数 | 激活得分+向量相似度 |
| 语义理解 | 无 | TF-IDF向量相似度 |
| 性能 | 遍历所有文件 | 数据库索引+FTS5 |
| 可扩展性 | 差 (O(n)) | 好 (O(log n)) |

## 实际效果

从测试结果看：

1. **精确匹配优秀**: "claude code mcp" 能准确找到3个高度相关文档
2. **语义理解良好**: "登录流程" 准确定位到IDE登录文档，得分250+
3. **噪音过滤有效**: "React" 只返回1个低分结果，说明过滤有效
4. **性能出色**: 6个文档，1247个n-gram，搜索几乎瞬间完成

## 可改进方向

1. **停用词优化**: 当前停用词列表较简单，可以扩展
2. **同义词支持**: 可以添加同义词词典
3. **拼音搜索**: 添加拼音索引支持模糊搜索
4. **上下文窗口**: 显示匹配片段的上下文
5. **相关文档推荐**: 基于向量相似度推荐相关文档
6. **增量索引**: 支持单文档更新而不是全量重建
