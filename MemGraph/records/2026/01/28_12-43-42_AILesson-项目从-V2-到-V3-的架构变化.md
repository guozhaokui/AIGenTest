## 问题

AILesson 项目从 V2 到 V3 的架构变化

## 解决方法

## V2 版本（旧版）

**目录**: `D:\work\AIGenTest\backend\mcp-lessons\`

**实现原理**:
- 单体架构：MCP Server 直接包含所有索引和搜索逻辑
- 存储：本地 JSON 文件 + 内存数据结构
- 索引方式：TF-IDF 文本匹配，没有真实向量
- 记录目录：`backend/mcp-lessons/records/`
- 核心文件：
  - `src/index.js` - 包含完整的索引、搜索、N-gram 处理逻辑
  - `src/storage.js` - JSON 文件读写
  - `data/live-gen.json` - 存储所有数据

## V3 版本（新版 - MemGraph）

**目录**: `D:\work\AIGenTest\MemGraph\`

**实现原理**:
- 微服务架构：MCP Client + MemGraph Service (FastAPI)
- 存储：SQLite 数据库 + FAISS 向量索引 + Markdown 文件
- 索引方式：
  - **激活式搜索**：多粒度 N-gram (char 2/3-gram, word 2/3/4-gram)
  - **向量检索**：使用 Qwen3-Embedding-8B (4096维) 生成真实语义向量
  - **混合评分**：N-gram 激活分数 + 向量相似度
- 记录目录：`MemGraph/records/YYYY/MM/`
- 架构：
  ```
  MCP Client (Node.js, index.js)
      ↓ HTTP (localhost:8800)
  MemGraph Service (Python FastAPI, server.py)
      ↓ HTTP
  GPU Server (192.168.0.132:6014)
  ```

**核心文件**:
- `src/server.py` - FastAPI 服务主程序
- `src/knowledge_indexer.py` - FAISS 向量索引 + SQLite 管理
- `src/activation_search.py` - 激活式搜索引擎
- `src/ngram_processor.py` - N-gram 处理
- `src/embedding_client.py` - 向量生成客户端
- `src/config.py` - 配置文件
- `data/knowledge.db` - SQLite 数据库
- `data/knowledge.faiss` - FAISS 向量索引

**MCP Client**:
- `backend/mcp-lessons/src/index.js` - 简化为纯 HTTP 客户端，转发请求到 MemGraph 服务

## 主要改进

1. **真实语义理解**：从 TF-IDF 升级到 4096 维语义向量
2. **更快的检索**：FAISS 向量索引比暴力搜索快数百倍
3. **服务化架构**：可独立部署、水平扩展
4. **持久化存储**：SQLite + FAISS 替代 JSON
5. **多粒度匹配**：字符级、词级 N-gram 提高召回率

## 迁移要点

1. **数据迁移**：旧的 JSON 数据需要重新索引到新系统
2. **服务启动**：MemGraph 服务需要单独启动（port 8800）
3. **MCP 配置**：更新 index.js 后需要重启 Claude Code
4. **依赖安装**：新增 Python 依赖（faiss-cpu, httpx 等）
