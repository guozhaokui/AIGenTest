## 问题

添加新文档后如何确保向量数据库持久化

## 解决方法

## 问题发现

原本的 `index_document` 方法只把向量添加到内存中的 FAISS 索引，但没有保存到磁盘：

```python
# 只在内存中添加
self.index.add(embedding)
self.conn.commit()
return doc_id  # ❌ 没有保存 FAISS 索引
```

这导致：
- ✅ 当前会话中可以搜索到新文档
- ❌ 服务重启后向量丢失

## 修复方案

在 `index_document` 方法的 commit 之后添加 `_save_index()` 调用：

```python
# knowledge_indexer.py
async def index_document(self, document: Dict) -> int:
    # ... 添加向量到内存
    self.index.add(embedding)
    
    # 提交数据库
    self.conn.commit()
    
    # 保存 FAISS 索引到磁盘 ✅
    self._save_index()
    
    return doc_id
```

## 更新机制说明

现在添加新文档时会**自动更新**：

1. **SQLite 数据库**（`data/knowledge.db`）
   - 文档元数据
   - N-gram 索引
   - 标签映射

2. **FAISS 向量索引**（`data/knowledge.faiss`）
   - 每次添加文档后立即保存
   - 使用 `faiss.write_index()` 持久化

3. **Markdown 文件**（`records/YYYY/MM/`）
   - 人类可读的备份
   - 可用于灾难恢复

## 批量添加优化

如果要批量添加多个文档，使用 `index_documents()` 方法更高效：

```python
# 批量添加 - 只在最后保存一次
doc_ids = await indexer.index_documents(documents)
```

它会在处理完所有文档后只调用一次 `_save_index()`，避免频繁的磁盘写入。
