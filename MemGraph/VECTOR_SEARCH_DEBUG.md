# 向量相似度搜索调试功能

## 功能说明

在调试面板新增了 **"向量相似度搜索"** 功能，可以根据输入的问题，列出所有文档向量按相似度排序的结果。

## 访问地址

```
http://localhost:8800/static/debug.html
```

滚动到页面底部，找到 **"🔍 向量相似度搜索"** 部分。

## 使用方法

### 1. 输入查询问题

在搜索框输入你的问题，例如：
- "如何在claude-code中添加mcp服务器"
- "claude code配置mcp"
- "ide登录流程"
- "项目构建发布"

### 2. 设置返回数量

在 `Top K` 输入框设置返回多少条结果（默认 10，最多 50）。

### 3. 点击搜索

点击 **"搜索"** 按钮或按回车键。

## 显示信息

### 查询统计

- **查询**: 你输入的问题
- **查询向量范数**: 查询向量的范数（应该接近 1.0）
- **嵌入耗时**: 生成查询向量的时间（通常 100-300ms）
- **搜索耗时**: 计算所有文档相似度的总时间
- **总文档数**: FAISS 中的文档数量
- **返回**: 实际返回的结果数量

### 结果列表

按相似度从高到低排序的表格：

| 列名 | 说明 |
|------|------|
| **排名** | 1, 2, 3... |
| **相似度** | 0.0-1.0，越高越相关<br>• 绿色 (>0.6): 高度相关<br>• 黄色 (0.3-0.6): 中度相关<br>• 橙色 (<0.3): 低度相关 |
| **文档ID** | SQLite 数据库中的文档ID |
| **FAISS索引** | FAISS 向量数据库中的索引号 |
| **路径** | Markdown 文件路径 |
| **标签** | 文档标签 |
| **向量范数** | 文档向量的范数（应该 ≈ 1.0） |
| **问题预览** | 文档问题的前 200 字符 |

### 点击查看详情

点击任意表格行，展开显示：
- **问题**: 完整的问题预览（200字符）
- **解决方法预览**: 完整的解决方法预览（200字符）
- **调试信息**: 角色、项目信息

## 调试用途

### 1. 验证语义理解

**测试用例**:
```
查询: "mcp服务配置"
预期: "如何在claude-code中添加mcp服务器" 应该排在前面
```

如果相似度合理（>0.6），说明语义理解正常。

### 2. 发现相似文档

输入一个问题，查看哪些已有文档与之相关：
- 相似度 > 0.8: 几乎相同的问题
- 相似度 0.6-0.8: 高度相关
- 相似度 0.4-0.6: 中度相关
- 相似度 < 0.4: 低度相关或无关

### 3. 调试向量质量

**检查项**:
1. **向量范数**: 所有向量的范数都应该接近 1.0
2. **相似度分布**: 不应该所有文档都是相同的相似度
3. **排序合理性**: 人工判断相似度高的文档是否确实相关

### 4. 对比不同查询

尝试不同的查询方式，观察相似度变化：

**示例**:
```
查询1: "mcp服务器配置"
查询2: "配置mcp"
查询3: "如何添加mcp"
```

对比三次搜索的相似度分数，理解语义理解的粒度。

### 5. 发现零向量问题

如果所有文档的相似度都是 0 或接近 0：
- 检查查询向量范数（应该 ~1.0）
- 检查文档向量范数（应该 ~1.0）
- 如果都是 0，说明向量生成失败

## 技术细节

### 相似度计算

使用 **余弦相似度**（归一化后的内积）:

```python
similarity = dot(query_vector, doc_vector)
```

因为向量已归一化（范数=1），所以内积等于余弦相似度。

**取值范围**: -1.0 到 1.0
- 1.0: 完全相同
- 0.0: 正交（无关）
- -1.0: 完全相反

实际中，大部分相似度在 0.0-0.9 范围。

### 向量维度

Qwen3-Embedding-8B: **4096 维**

### 性能

- 嵌入耗时: ~150ms（取决于 GPU 负载）
- 搜索耗时: ~5ms（6个文档）
- 总耗时: <200ms

## 使用场景

### 场景1: 验证新文档是否重复

添加新文档前，搜索相似问题：

1. 输入新文档的问题
2. 查看 Top 3 结果的相似度
3. 如果相似度 > 0.8，可能是重复文档

### 场景2: 找到相关文档补充信息

在写新文档时，查找相关旧文档：

1. 输入新文档的核心概念
2. 查看相似文档
3. 参考已有的解决方案

### 场景3: 评估搜索质量

定期测试一些标准查询：

```
查询: "配置mcp"
期望: 所有 mcp 相关文档排在前面

查询: "登录"
期望: 登录相关文档排在前面
```

记录相似度分数，评估搜索质量是否稳定。

### 场景4: 调试向量生成问题

如果主界面搜索的向量相似度异常：

1. 在调试面板搜索同样的问题
2. 检查查询向量范数
3. 检查文档向量范数
4. 查看详细的相似度分数
5. 定位问题所在

## 与主搜索的区别

### 主搜索 (http://localhost:8800)

- **目的**: 最终用户使用
- **算法**: 激活式搜索 + 向量相似度
- **排序**: 综合得分（激活 + 向量）
- **显示**: 简化的相似度信息

### 调试搜索 (debug.html)

- **目的**: 开发者调试
- **算法**: 仅向量相似度
- **排序**: 纯向量相似度
- **显示**: 完整的技术指标

## 注意事项

1. **搜索需要时间**: 第一次搜索需要生成查询向量，约 150ms
2. **结果可能不同**: 调试搜索仅用向量，主搜索结合了 n-gram
3. **相似度阈值**: < 0.3 的结果通常不相关
4. **向量范数**: 如果不是 ~1.0，说明归一化有问题
